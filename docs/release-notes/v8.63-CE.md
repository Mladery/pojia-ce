# 破甲一键通 8.63-CE

**自己会更新了；DSH 的 `bash` 工具不再要求「完全访问」才肯跑。**

两条都跟「用起来卡手」有关：一条是每次换新版都要手动下来再覆盖，另一条是 DSH 里只要动 shell 就报 `0xC0000142`，逼着人把沙箱整个关掉。

## 这个版本做了什么

### 更新检查：只提示，装不装你点按钮

```
破甲一键通 --check-update     # 只问一句，不动文件
破甲一键通 --update           # 有新版就下、校验、替换
```

三个入口，同一套逻辑：命令行 `--check-update` / `--update`，菜单里的 `[u] 检查更新`，以及图形界面顶栏下那条提示 —— 查到新版就亮出「安装 v8.63」按钮，按下才下载，旁边有「以后再说」（这个版本内不再问）。**任何一处都不会自己下载、自己替换、自己重启。**

版本比较只看 tag 的数字段（`v8.63-CE` → `(8, 63)`），`-CE` 后缀不参与 —— 否则上游发个 `v8.63` 就会被判成「不同版本」来回刷。资产名按平台定死：Windows 取 `pojia-ce-windows-x64.exe`，macOS 按 `arm64` / `x64` 分，其余 `linux-x64`。

下载不认「HTTPS 就够了」：同一批 Release 里的 `SHA256SUMS.txt` 一并取下来比对，对不上就删文件、报错、不安装。构建脚本写的是 `sha256sum ./*`，条目形如 `hash  ./文件名`，所以按 basename 比 —— 只比文件名会一条都对不上，然后静默退化成「没表可依」，那等于没校验。表能读到但没有本平台那一行，同样不装（发布不全）。没有 `SHA256SUMS.txt` 的早期 tag 照装，但会在输出里说一句。

**Windows 不能自己覆盖自己。** 正在运行的 exe 被锁着，`os.replace` 必然失败。所以写一个 `_update.bat`：等 4 秒轮询到主进程退出，再 `move /y` 顶掉，最后把 `.bat` 自己删了。POSIX 上 `os.replace` 原子替换就够。源码态（非冻结）拒绝替换 —— 那种情况下「替换」等于覆盖正在被 git 管的 `.py`。

**只查，不装。** 启动时（以及打开图形界面时）查一次「有没有新版」，结果缓存在 `状态/_update.json` **一天**，过期才再发请求：不然每次开都多几百毫秒，还得罪一遍 GitHub 的限流。查到了只做两件事 —— 顶栏下多一条提示，和一个「安装 v8.63」的按钮。装不装、什么时候装，由按按钮的人决定；从不自动下载、自动替换、自动重启。

命令行等价物：菜单里按 `u`（查到再问一次要不要装），或者 `--update`。

**这条不违背「无遥测 / 无静默更新」，前提是口径写准。** 那次检查只读 GitHub 公开的 `releases/latest`：不带任何本机信息（无设备标识、无 query、无使用统计），结果缓存一天，而且可以关 —— `--no-update-check`、环境变量 `POJIA_NO_UPDATE_CHECK=1`、界面上的「以后再说」。README 和免责声明里原本写的是「唯一的外部连接是 `--install-git`」，这一版改成三处并逐条写明：`--install-git`、版本检查、安装更新。承诺里不该留一个「我们只是查一下」的漏洞 —— 宁可把动作摆出来让人自己关。

### `bash` 工具报 0xC0000142：不是 DLL 的错

DSH 里调 `bash`，退出码 `3221225794` —— 也就是 `0xC0000142`，`STATUS_DLL_INIT_FAILED`。名字很误导，DLL 一点问题都没有。手工复现能拿到真话：

```
runner.js --mode read-only -- bash -c "echo hi"
→ couldn't create signal pipe, Win32 error 5
```

Git Bash 是 MSYS2 运行时，启动第一件事是建一根 signal pipe。沙箱把子进程塞进 `WRITE_RESTRICTED` 令牌（完整性降到 Low，restricting 列表 = 登录 SID + Everyone + 工作区 + 临时目录），msys 建管道时自带 `SECURITY_ATTRIBUTES`，写进去的那份 DACL 里没有任何一个 restricting SID —— `CreateNamedPipeW` 直接 `ACCESS_DENIED`，msys 就以 `0xC0000142` 退出。**只有切到「完全访问」才跑得动**，正是大家报的那个现象。

三个「大概是它」的假设都试过，都不是：

| 假设 | 改法 | 结果 |
|---|---|---|
| 完整性降到 Low 导致 | 去掉 `restrictTokenIntegrity` | 仍 0xC0000142 |
| restricting 列表缺 INTERACTIVE | 加 `S-1-5-4` | 仍失败 |
| 令牌 default DACL 只授了一个 SID | 对全部 restricting SID 授予 | 仍失败 |

反过来验证：同一套受限令牌下 `cmd.exe`、`powershell.exe`、`python.exe` 全部 exit 0；Python 在沙箱里 `os.pipe()` 和不带显式 DACL 的 `CreateNamedPipeW` 也都正常。**问题只在 msys 那份自带 DACL 的管道上。**

沙箱一行没动 —— 换的是 shell 实现：`busybox-w32` 的 `sh`（ash），原生 Win32、静态链接、不建命名管道，同样的令牌下跑得干干净净。`workspace-write` 模式复核过：`echo > 工作区/ok.txt` 成功，`echo > 工作区/../outside.txt` 仍是 `Permission denied`，写限制原样生效。

### 换法是插件，不动宿主文件

`LocalBashExecutor.execute()` 里写死 `['bash', '-c', spec.command]`，但它调的是自己的 `executeArgv(spec, argvOrPrepare, onStarted)`。插件包一层就够了：

```javascript
shell.executeArgv = (spec, argvOrPrepare, onStarted) => {
  if (typeof argvOrPrepare === "function") {
    return orig(spec, async (s) => swap(await argvOrPrepare(s), bb), onStarted);
  }
  return orig(spec, swap(argvOrPrepare, bb), onStarted);
};
```

`argvOrPrepare` 有「数组」和「返回 argv 的函数」两种形态，只认前者的话，凡是带 signal 的调用都会漏掉。`swap` 只改首项恰好是 `bash` 的，`git status` 这类原样透传。

同一个插件里顺手修了 PATH：`System32\bash.exe` 是 WSL 入口，Windows 的系统目录排在用户目录前面，不前置 Git 的 `bin` 的话命令会被 WSL 接走，报出来的路径全是 `/mnt/c/...`。

busybox 是**内嵌**的（`BUSYBOX_B64`，zlib + base64，解压后 sha256 钉在 `BUSYBOX_SHA256`）。装插件时落到插件目录，大小一致就不重写，解不出来或没落盘就退回 Git Bash 并在 `--status` 报 warn。代价是源码从 572 KB 涨到 1.16 MB —— 换离线可用，认了。

### 但工具名还叫 `bash`

底下跑的是 ash，名字还叫 bash，模型会照 bash 写：`arr=(a b)`、`[[ ]]`、`<<<`、`<(...)`、`{a,b}`、`$'...'`、`mapfile`、`local -n` —— 然后一条一条报语法错。

改名做不到：`defineTool({ name: 'bash', ... })` 是 `tool-bash` 里的字面量，`ToolsService.register()` 只能新增或遮蔽，`restrict()` 只能放行或拒绝，没有「换个名字挂上去」的口子。

所以改语义。插件往 systemPrompt 里塞一段：

```javascript
scope.systemPrompt.context({ name: "pojia:shell-dialect", order: 117, text: () => ASH_NOTE });
```

`order` 取 117，排在 `SANDBOX_POLICY`(110) 和 `APPROVAL_POLICY`(115) 后面 —— 这条是「怎么写命令」的执行细节，不该盖在策略前面。正文直接点名 `busybox ash`、逐条列出不能用的 bash 独有语法，并给出替代写法（进程替换 → 先写中间文件）。

## 升级

覆盖旧的脚本 / 可执行文件即可，或者直接 `--update`。本次没有改动任何靶点的注入正文，**已破甲的机器不需要重跑**。

装过 Git Bash 接管的机器建议重跑一次 `--target dsh`（或界面里重新勾一次 Git Bash 开关）：插件目录里会多出 `busybox.exe`，`--status` 从 warn 变成 ok，`bash` 工具在受限沙箱里就能用了。

## 已知限制

- 自更新只处理本工具自己。`--update` 不会顺带升级 `persona.md` 或人格库 —— 那些是你的文件，不会被覆盖。
- 替换完成后需要重新启动才生效（Windows 那条 `_update.bat` 是在主进程退出后才动手的，退出即结束）。
- busybox 是 GPLv2。它只作为独立可执行文件落盘并被调用，不链接进本工具；源码见 [frippery.org](https://frippery.org/busybox/)。
- ash 不是 bash。真需要 bash 独有语法的场景（数组、`[[ ]]`、进程替换），插件里有兜底开关 `busybox: ""`，配空即退回 Git Bash，代价是受限沙箱下必然 `0xC0000142`。
