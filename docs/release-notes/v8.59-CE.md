## 这个版本：检测状态和破甲，对同一台机器说同一句话

有人实测：另一台机器上，检测状态对 DSH 报 **0 套**，破甲报 **1 套**，来源写的是「进程反查」。

定位链本来就是共用的（进程 → 切换工具配置 → 快捷方式 → 盘符根目录 → 有界遍历），差的不是代码，是**运行时机**：进程反查读的是正在跑的进程命令行，客户端关着就什么也读不到；而检测通常关着跑，破甲往往开着跑。中间又没有任何一层把这次查到的结果留下来。

### 三条修法

1. **命中就记住。** 破甲时任何一层命中，都把安装根写进 `状态/发现目录.json`；下次检测直接复用，不再赌「客户端这一刻开着没开」。只读与预演一律不写 —— `--status` 自述「不改盘」，这句话不能破。
2. **盘符根目录按名字嗅探。** 每个盘符只 `listdir` 一层，名字里带 `dsh` / `deepseek` / `harness` 再验安装根判据。`D:\DSH Desktop` 这种自定义一级目录一次就中，比最后那层有界遍历便宜两个数量级。
3. **只读也能看见 asar 里的安装。** 不解包，只读 `app.asar` 头，确认里面真打包着 `dsh-agent-instructions` 就记一笔。检测状态于是报「检测到 1 套：插件在 app.asar 内，尚未解包」，而不是「没探测到」；已经解包到 `resources/app/` 或 `.unpacked/` 的不会重复计数。

### 顺手统一的三处口径

- **标记块目标**（Codex / Cursor / Claude / Gemini / Qwen / iFlow / Trae / CodeBuddy / OpenCode / Windsurf / Cline / Copilot / Kiro）：`locate()` 成为唯一定位入口，检测、体检、破甲都调它。以前 `check()` 自己写了一份不实扫的探针、破甲侧完全不探 —— 检测能给「安装目录在 X」，破甲只丢一句「未检测到」。
- **ZCode**：检测把「找到 `zcode.cjs`」算作已安装，破甲却只认配置目录。现在三处共用一个判断；只找到 cjs、配置目录还没生成时，破甲会说清下一步该干嘛。
- **桌面端三个目标**（DSH / WorkBuddy / 国际版）：缓存入口统一，`--dry-run` 不落盘。

### 顺带修掉一个死开关

`_maybe_unpack()` 判的是 `allow_unpack`，而全仓库只有 `_unpack_ok` 有赋值 —— 自动解包其实一直没真执行过，`resources/app/` 只可能是旧版本或用户自己解的。修回之后，`--apply` 才会在需要时真的解包；`--status` 仍然只读。
