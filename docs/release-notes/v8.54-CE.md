# 破甲一键通 8.54-CE

免安装单文件可执行文件。不用装 Python，不用装依赖，下载后放任意目录直接跑。

## 下载

| 平台 | 文件 |
|---|---|
| Windows x64 | `pojia-ce-windows-x64.exe` |
| Linux x64 | `pojia-ce-linux-x64` |
| macOS Apple Silicon | `pojia-ce-macos-arm64` |
| macOS Intel | `pojia-ce-macos-x64` |

Linux / macOS 下载后先 `chmod +x`。双击直接进图形界面；想走命令行菜单加 `--menu`。

## 这个版本：macOS 的「破甲完打不开」

不是权限问题，是**代码签名**。

macOS 上的客户端都是 `.app` 包，`.app` 的签名 seal 覆盖整个包内文件树。破甲往里写东西（asar 解包出的 `Contents/Resources/app/`、`managed-prompts/`、`.bak` 备份）之后 seal 就不匹配了：

- **刚下载、一次都没启动过的包**（带 `com.apple.quarantine`）再启动时，Gatekeeper 会重评整个 bundle，直接报「已损坏，无法打开」；
- 已经启动过一次的，不再走那次评估，通常照常能开。

同一份产物，**先启动过再破甲就没事，先破甲再启动就炸** —— 这种看顺序的 bug 最容易被误判成「这工具把软件搞坏了」。

### 修法

改完包内文件后自动 ad-hoc 重签：

```
codesign --force --deep --sign - /Applications/Xxx.app
```

身份写 `-` 就是不依赖任何证书的本机自签。重签后厂商签名变成自签名，首次打开要右键 → 打开 —— 比打不开强，而且包本来就已经被改过了。

**只在真动过 `.app` 时才签。** 守护任务每 5 分钟写的是 `~/.workbuddy/`，那在包外面；每次触发重签等于每 5 分钟扫几百 MB 的包。实现上不做猜测，而是在写入（`write_text`）、删除解包目录（`_asar_drop`）、还原（`revert_traces`）三处收口记账，收尾统一签一次；预演不记账。

### 新命令

```bash
pojia-ce --mac-check                     # 扫 /Applications 和 ~/Applications，只读
pojia-ce --mac-check "/Volumes/X/DSH Desktop.app"
pojia-ce --mac-check --resign            # 把签名失效的包签回去
```

只认得的客户端包才进候选（DSH Desktop / WorkBuddy / Cursor / Trae / Windsurf / Kiro / CodeBuddy / ZCode / iFlow / Claude / Codex），不会去重签 Safari。

已经卡住打不开的，两条手动命令（macOS 自带）：

```bash
codesign --force --deep --sign - /Applications/Xxx.app
xattr -cr /Applications/Xxx.app
```

### 一条不能碰的红线

解包 asar 走的是「`resources/app/` 目录优先于 `app.asar`」的 Electron 加载规则，**`app.asar` 本体全程不动**。Electron 30+ 在 macOS 上默认开启 `EnableEmbeddedAsarIntegrityValidation`，`app.asar` 的哈希锁在 `Info.plist` 里 —— 一旦改成重打包 asar，应用会直接崩溃退出，比签名失效严重得多。

### 其它

- 客户端要**连托盘一起退干净**再重开（`Cmd+Q` 不够），否则注入不生效。
- `/Applications` 里的包要求属主是你自己；装到 `~/Applications` 或别处更省事。
- 非 macOS 平台上这些逻辑一行都不执行：`--mac-check` 只打印一句提示就退出，也不会凭空报「签名坏了」。
