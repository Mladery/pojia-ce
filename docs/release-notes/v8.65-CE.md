# 破甲一键通 8.65-CE

**Linux 和 macOS 也有安装包了：装、升级、卸载，一个文件。**

上一版给 Windows 做了 setup.exe，另外两个平台还是两个没有扩展名的二进制躺在 Release 里。这一版补齐，形态和 Windows 对齐。

## 下哪个

| 平台 | 安装包（推荐） | 免安装 |
|---|---|---|
| Windows x64 | `pojia-ce-windows-x64-setup.exe` | `pojia-ce-windows-x64.exe` |
| Linux x64 | `pojia-ce-linux-x64-installer.run` | `pojia-ce-linux-x64` |
| macOS Intel | `pojia-ce-macos-x64-installer.command` | `pojia-ce-macos-x64` |
| macOS Apple Silicon | `pojia-ce-macos-arm64-installer.command` | `pojia-ce-macos-arm64` |

## 装到哪

`~/.local/share/pojia-ce`，命令行入口软链到 `~/.local/bin/pojia-ce`。

**不需要 sudo。** 这不是随便挑的：装到 `/usr/local` 或 `/opt` 的话，`--update` 每跑一次都得提权，自动更新就废了 —— 而那正是 v8.63 刚做好的东西。Windows 装 `%LOCALAPPDATA%` 是同一个理由。

代价是 `~/.local/bin` 默认不在 PATH 里。安装时问一句要不要写进 shell 配置；`--yes` 模式（自升级走这条）不问，也不碰你的 dotfile。

## 一个文件干三件事

```sh
sh pojia-ce-linux-x64-installer.run     # 交互：确认目录、要不要加 PATH
sh ... --yes --quiet                    # 非交互，自更新走这条
pojia-ce --uninstall                    # 删程序，留 状态/ 和 历史备份/
pojia-ce --uninstall --revert           # 删之前先把已改的提示词还原
pojia-ce --uninstall --purge            # 连用户数据一起删
```

头部是一段 sh，尾部贴着一份 tar.gz，中间一行标记当分隔。三个平台共用同一个模板，只有扩展名不同：Linux 是 `.run`，macOS 是 `.command`（双击能在终端里跑）。

macOS 的包第一次打开可能被 Gatekeeper 拦，右键 → 打开。

## 再跑一次就是升级

解到临时目录 → 新目录里没有的旧文件逐个搬过去 → 旧目录整个换掉。

数据搬运是「新目录里没有的都搬过去」，不是白名单列举 —— 列举写死的话，以后加个新目录就丢数据。

## 程序认得出自己是装出来的

Windows 靠注册表，POSIX 靠安装目录里的 `install.json`（prefix / version / asset / 安装时间）。判定要求 `prefix` 和当前目录对得上：装好的目录被整个复制走，那份仍按绿色版处理，否则升级会往副本里铺一整套。

认出来之后，`--update` 才会去下 `*-installer.run` 而不是裸二进制。拿错的后果不是「版本没变」，是新版多出来的 `.so` 一个都没到位。

安装态的自更新走 `_update.sh`：等本进程退出（`kill -0` 轮询，300 次上限），再静默跑一遍安装包，最后把程序拉起来。它脱离终端运行 —— GUI 是从终端拉起来的，你关掉那个窗口不该把升级半截掐死。

## 卸载为什么交给程序自己

POSIX 上 unlink 一个正在运行的可执行文件是合法的：进程拿着已经打开的 inode 跑完，磁盘上那份就没了。所以 `pojia-ce --uninstall` 可以自己删自己，顺便把软链和 `.desktop` 一起摘掉。Windows 删不掉运行中的 exe，那边只能由安装程序负责。

## 顺带修掉的三处

**载荷被切错位置。** 模板里 `awk '/^__POJIA_PAYLOAD_BELOW__$/ ...'` 也写着这个分隔字符串，构建脚本用 `split()` 切，一刀切在 awk 那行上，剩下的头部连引号都不闭合。改成从最后一次出现处切。

**tar 里混进了反斜杠。** Windows 上构建时 `os.path.join` 给的是 `pojia-ce\pojia-ce`，Linux 解出来就是个名字里带反斜杠的文件。tar 的路径分隔符永远是 `/`。

**卸载保留数据，结果装不回去了。** 原来的保护是「目录非空且没有 install.json 就拒绝」，卸载一次留下 `状态/` 之后，每次重装都被自己拦。改成白名单：认得的数据项允许合并，认不出的照样拒绝 —— 下面紧接着是 `rm -rf`。

## 验证

```
Windows   271 passed, 6 skipped（6 条是 POSIX 专用）
WSL       275 passed, 2 skipped（没装 node）
```

WSL 里用真产物跑了一遍全链路：装 → `--version` 出版本号 → 造数据 → 再装一次（数据都在）→ 卸载（程序没了、数据留着、软链和 `.desktop` 都摘了）→ 重装。CI 上 Linux 和 macOS 各有一条「装一遍、跑一次、再卸掉」的冒烟。

## 本版补丁：CI 上才露头的两个 bug

打包脚本在本机全通，推上去第一次跑 CI 就红了 —— 两处都是「Linux 上行、macOS 上不行」。

**变量后面紧跟中文，变量名被多算一个字节。** macOS 的 `/bin/sh` 是 bash 3.2，扫变量名时会把紧跟着的那个汉字的首字节吃进去：`$PREFIX」` 被当成变量 `PREFIX<0xE3>`，未定义 → 整个值变空，剩下的 `80 8D` 还不是合法 UTF-8。改成 `${PREFIX}` 显式定界，模板里同类写法一并改掉，另加一条静态测试守着。

**`/var` 是 `/private/var` 的软链。** 安装器按 `mktemp -d` 给的 `/var/folders/...` 写 `install.json`，程序跑起来按 `/private/var/...` 算当前目录，两边都用 `abspath` 比就永远不相等 —— 结果是 `--uninstall` 静默返回 1，`--update` 还认不出自己是安装版、跑去下裸二进制。判据改走 `realpath`。

## 校验

`SHA256SUMS.txt` 与本批产物同批上传。Windows 的 exe 另外有签名；Linux / macOS 只有 SHA-256 这一条路。
